# Lifting Plan Calculator 2.10.0

**Released 16 November 2026** · Linux (AppImage) · Windows 10/11 (x64)

Releases are now signed, and the app refuses an update it cannot attribute.

## What changed

- **The checksum manifest is signed.** Every release carries
  `SHA256SUMS.txt.sig`, an Ed25519 signature over `SHA256SUMS.txt`. The public
  key is compiled into the application, so the Windows updater can prove the
  manifest came from this project before it reads a single digest from it.

- **An unattributable update is refused.** The updater verifies the signature,
  then the installer's SHA-256 against the manifest. A missing signature, a
  wrong key, a changed manifest or a mismatched file all delete the download and
  stop; nothing is run.

- **One key, one owner.** The private key lives on the maintainer's machine
  (mode 0600) and in the `UPDATE_SIGNING_KEY` repository secret; it is never in
  the repository. `scripts/update-signing-key.sh` performs the ceremony in one
  step and prints the command that stores the secret.

## What this does and does not prove

It proves **authorship**: an object signed by this key came from whoever holds
it. Combined with the digest check it closes the gap left in 2.9.4, where the
manifest was fetched from the same place as the installer.

It does not replace Windows code signing. The installers still carry no
Authenticode certificate, so SmartScreen still shows "Unknown publisher" for a
manual download. The in-app update path no longer depends on that warning: it
checks the project's own signature instead.

## If you lose the key

The private key cannot be recreated. Without it no new release can be signed, and
every installed copy refuses an unsigned manifest. Recovery means publishing a
build carrying a new public key, which users install manually once. Keep a backup
of `~/.config/lifting-plan-calculator/update-signing.key` somewhere safe.

## Notes

- Users on 2.9.x are updated through the digest-only path; 2.10.0 is the first
  build that enforces signatures, and it is itself signed.
- Nothing about the calculation, the report, or the PDF export changed.

## Compatibility and upgrade notes

- glibc 2.35 floor — Ubuntu 22.04+, Fedora 36+, Arch.
- No plan is stored between launches, so there is nothing to migrate.
- Windows needs the WebView2 runtime, as before.
