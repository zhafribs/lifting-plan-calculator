# Lifting Plan Calculator 2.9.4

**Released 16 November 2026** · Linux (AppImage) · Windows 10/11 (x64)

The Windows update path now checks what it downloaded before running it, and the
release build pins the tools that produce the artifact.

## Fixes

- **An installer is verified before it runs.** The updater fetches the release's
  `SHA256SUMS.txt`, finds the installer by name, and compares the SHA-256 of the
  downloaded file. If the manifest is missing, the installer is not listed, or
  the digest differs, the file is deleted and nothing is executed. A truncated
  or substituted download can no longer be run by accident.

- **The build tools are pinned.** The release workflow downloads the pinned
  Tauri CLI archive to a file, verifies a hard-coded SHA-256, and only then
  extracts it; the cache key includes that digest. The binary that builds the
  artifact is no longer taken on trust.

- **KaTeX and the bundled fonts are now covered by the vendored-code check**,
  alongside pdf.js. A changed vendored file shows up as a failed check and a
  reviewable manifest diff.

## What this does and does not prove

This verifies **integrity**, not **authorship**: the checksum manifest is served
from the same release as the installer, so a compromised release can replace
both. It catches corruption, truncated downloads and a mismatched asset — the
things that go wrong without an attacker. Signing the manifest with a key whose
public half ships in the app is the remaining step; it needs a signing key and is
not claimed here.

## Notes

- An offline machine, or GitHub's API being unavailable, now means the in-app
  installer reports that the checksums could not be read instead of proceeding.
  The release page remains the fallback.
- Nothing about the calculation, the report, or the PDF export changed.

## Compatibility and upgrade notes

- glibc 2.35 floor — Ubuntu 22.04+, Fedora 36+, Arch.
- No plan is stored between launches, so there is nothing to migrate.
- Windows needs the WebView2 runtime, as before.
