# Lifting Plan Calculator 2.8.0

**Released 14 November 2026** · Linux (AppImage) · Windows 10/11 (x64)

*Save as PDF* now works on Windows even if Microsoft Edge has been removed or
disabled, the footer no longer depends on which engine printed, and the Summary
page view keeps up with you while you type.

## Highlights

- **Windows printing no longer depends on Edge.** The export prints with the
  WebView2 runtime the app already needs in order to start — the same engine
  that draws the window. Uninstalling the Edge browser no longer takes the PDF
  export with it. If that runtime cannot print, the Edge or Chrome already on
  the machine is still tried before the app reports a failure.

- **One footer, drawn by the app.** The reference, credit line and `n / total`
  are written onto the finished pages on Windows as well as Linux, instead of
  being left to the engine's `@page` rules. A runtime older than Chromium 131
  used to drop those rules silently; that can no longer happen, and the two
  platforms now agree on the footer.

- **The page view follows your typing.** It redraws about a second after you
  stop typing instead of waiting for you to leave a field. The **Live** view is
  still instant, and the saved PDF is still the document you were looking at.

## Notes

- **What "inside the app" means on Windows.** The WebView2 runtime is the
  component the app already requires to start; this change stops the export from
  needing the separate Edge *browser*.
- **The Windows path is now exercised on every change.** CI builds the app on
  Windows and exports a probe report through it, checking that a real PDF comes
  out; before this release, Windows printing was compiled but never run.
- **Linux is unchanged**: WebKitGTK prints and the footer is stamped the same
  way as before.
- No calculation, chart or report layout changed in this release.

## Compatibility and upgrade notes

- glibc 2.35 floor — Ubuntu 22.04+, Fedora 36+, Arch.
- No plan is stored between launches, so there is nothing to migrate.
- Windows needs the WebView2 runtime, as it did before.
