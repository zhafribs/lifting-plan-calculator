# Lifting Plan Calculator 2.9.3

**Released 16 November 2026** · Linux (AppImage) · Windows 10/11 (x64)

Two security fixes from the audit: a malformed workbook can no longer take the
app down with it, and Windows no longer opens files through a shell.

## Fixes

- **A hostile load chart can no longer exhaust memory.** A workbook that declares
  a huge used area — cells at `A1` and `XFD1048576`, for example — used to make
  the spreadsheet parser allocate the whole rectangle before any limit applied.
  That is hundreds of gigabytes, so the app aborted the moment the file opened
  and the unsaved plan went with it. Sheets are now read cell by cell under a row
  limit, a column limit and a total-cell budget, and an over-large sheet is
  refused with a message instead of being built.

- **The 24 MB workbook limit is applied before the file is read.** Previously the
  whole file was loaded first and the limit checked afterwards, so an oversized
  file was read into memory before being refused.

- **Windows opens reports and links without `cmd`.** The old path built
  `cmd /C start "" <target>`, where an `&` in a file name or a URL starts a
  second command. The opener now uses the Windows shell API directly, so the
  target is data and no command line is parsed.

## Notes

- Load charts are small tables. A sheet wider than 256 columns, or a workbook
  with more than 400,000 cells across all sheets, is refused as "larger than a
  load chart". The two example charts and normal manufacturer exports are far
  below that.
- Sheets taller than 2,000 rows are cut at that row, as before.
- Nothing about the calculation, the report or the PDF export changed.
- The fix was found by a full repository audit; the remaining findings (release
  signing and checksum verification in the updater, pinned build tools, CSP) are
  separate work and are not claimed here.

## Compatibility and upgrade notes

- glibc 2.35 floor — Ubuntu 22.04+, Fedora 36+, Arch.
- No plan is stored between launches, so there is nothing to migrate.
- Windows needs the WebView2 runtime, as before.
